# 表达向量索引存储与恢复

索引主 JSON 的版本和 embedding profile 标识不变。`vectors_file` 兼容旧 NPZ，
也可指向 `expression-arrays-*.json` 存储清单。新清单引用归一化 float32 NPY 基矩阵，
以及可选的增量 NPY 和行号。每一代不可变，查询持有快照，发布使用已有更新锁和原子主清单切换。

## 老用户升级

无需修改配置。旧格式继续可读，在下一次成功的表达更新时转换为新格式。
不重新请求已有 embedding，不清零 BOOTSTRAPPING/STABLE 状态、模型空间或重聚类变化计数。
首次转换保留旧 NPZ，并尝试保存 `索引文件名.pre-npy.bak`；备份失败会 warning，不阻断转换。
备份以 `.pre-npy.bak` 的创建写入时间（mtime）计保留 7 天。到期后在下一次索引加载或成功更新时，
校验当前新代数组可读且旧 NPZ 不再被索引引用，再删除这两个备份文件。程序未运行时不会按钟点执行删除；
文件占用或校验失败记录 warning，最多每小时重试一次，不影响业务。
降级旧程序前需人工恢复对应的旧主 JSON 和 NPZ，不能仅把新 NPY 改名。

旧 NPZ 首次加载仍需解包和校验，会有一次性内存/磁盘开销。临时大数组采用磁盘映射，
小于 8 MiB 的计算直接使用内存。维护后的 JSON 元数据仍整体写入，向量数据不再每批全量复制。

## 增量和内存边界

更新复用只读行视图。向量增量相对于基矩阵保存，不形成无限版本链；新查询同时读取基矩阵和增量。
相对基矩阵的变化达到 5%、增量超过 32 MiB，或距上次合并超过一小时后，在下一次更新时分块合并。
这里没有额外的后台定时任务。删除通过新清单的逻辑行布局生效；大规模重排自动触发合并。
磁盘合并和全量重聚类是独立条件，合并不清零重聚类计数。

归一化、矩阵写入、簇中心累加、k-means 相似度和 MMR 使用约 8 MiB 的向量块，
同时仍有 O(N) 的行索引、标签和分数。该上限不是整个进程 RSS 的硬上限；
文件映射的活跃页面、新旧查询快照及 Python 元数据仍占用内存。

## 错误处理

- 旧元数据中的少量无效记录、旧向量中的零值/非有限值、少量越界引用会记录 warning 并跳过。
  每类按该批记录的 1% 限制（小索引最多允许 1 条），不能把整个索引丢空。
- 过滤旧记录前固定原向量行号，避免删除一行导致后面的表达与向量错配。
- 索引派生记录被剔除不会删除表达数据库记录；成功发布后可由原历史回填流程重新补齐。
- 超限损坏、维度错误、缺失关键文件、无有效聚类中心等关键错误会暴露，不能发布不完整新代。
- 新数组及存储清单写入并 fsync 后，才原子发布主 JSON。失败保留旧主清单；下次同步可以重试。
- Windows 映射占用（WinError 32/33）记录 debug，不打印堆栈；其他删除失败保留 warning 和堆栈。
  发布成功后将旧代登记为退役。查询、更新以及 NumPy 行视图共同持有根映射；
  最后一个引用消失后，由后台回收线程关闭映射并删除该代的独占文件，不等待固定宽限时间。
  新代仍引用的共享基矩阵受到保护。发布、映射打开和回收使用同一把锁，避免引用登记与删除竞态。
  finalizer 只发送通知，不在主事件循环关闭映射、读文件或执行删除；异步查询取消后，
  尚未结束的工作线程仍持有引用，不会被提前回收。
  实际 IO 失败保留待回收记录，每分钟重试；已隔离文件不影响回收。
  每小时最多一次的全目录扫描仅处理崩溃遗留或未登记的旧代，不再决定正常旧索引何时释放。
  已隔离的 `*.corrupt-YYYYMMDD-HHMMSS.json` 不参与活动索引扫描，也不会被清理器删除。
  活动主清单损坏仍会推迟回收，以保护无法确认引用关系的数据。
  无法确认引用关系时推迟清理，不阻断索引更新。
- 不强制关闭仍被查询持有的映射，不自动清空数据库，不通过补零伪造合法向量。

## 验证

`uv run --no-sync pytest pytests/common/test_expression_vector_storage.py pytests/maisaka/test_replyer_expression_selection.py -q`

覆盖旧 v1/v2、归一化一致性、部分坏数据及行号对齐、BOOTSTRAPPING 元数据保留、
增量连续修改/新增/删除、重启读取、比例与时间合并、发布拒绝、磁盘失败、Windows 清理失败及共享基文件保护。

发布日志 `表达向量发布耗时` 分别记录数组持久化、JSON 编码、主清单发布和清理耗时及线程名，
用于与事件循环看门狗告警对照。检索的候选过滤、向量打分和 MMR 在线程池中执行；
线程池不能消除所有 GIL 竞争，不能仅因时间相邻就把卡顿归因于文件占用。
