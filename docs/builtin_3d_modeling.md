# 内置三维建模工具

MaiBot 的 Maisaka 工具目录内置四个三维工具。它们按需发现：需要建模时，Planner 可通过 `tool_search` 搜索“三维建模”“3D”“模型渲染”等关键词，再调用对应工具。

这四个工具由实验性开关 `experimental.enable_3d_modeling` 统一启停，默认关闭。开关关闭时，工具既不出现在可用工具列表，也不会被 `tool_search` 搜索到；开启后需重启或重载配置才会生效。

首版提供参数化组合建模、静态网格导入、部件编辑和 CPU 预览渲染。使用 `trimesh`、NumPy 和 Pillow，不需要 Blender、OpenGL、显卡或外部模型生成 API。更新代码后用 `uv sync` 安装项目依赖，并在下次启动 MaiBot 时加载新工具。

## 工具

| 工具 | 用途 |
| --- | --- |
| `create_3d_model` | 用具名的方块、球体、圆柱、圆锥、圆环组合创建模型，返回模型编号与 GLB/STL 文件路径。 |
| `inspect_3d_model` | 查看已有模型的部件、尺寸、包围盒和面数；也可导入工作区中的 OBJ/STL/PLY/GLB 文件。 |
| `edit_3d_model` | 添加、删除部件，平移、旋转、缩放、改色；输出新模型版本，保留原件。 |
| `render_3d_model` | 从指定角度生成 PNG，将真实图片作为工具媒体返回 Planner 上下文。 |

可以直接向麦麦提出“做一个蓝色圆顶的小房子，渲染给我看看”“把刚才模型的底座加宽，再从上方看一次”等请求。模型负责把自然语言设计转换成这些结构化工具参数；几何工具自身不执行自由形式代码。

## 看图与继续修改

渲染结果通过 `ToolContentItem(image)` 接入现有上下文链路，媒体索引为 `tool_result:<call_id>:1`。Planner 可以看图后继续编辑、再次渲染。需要展示给聊天用户时，使用现有 `send_image` 的 `media_index`，或丰富性回复的 `attach_pic`，引用这个媒体索引。

要让 Planner 实际看见渲染图，需要已有视觉配置满足：

- `visual.planner_mode` 为 `auto` 或 `multimodal`。
- Planner 任务中的候选模型支持图片输入，且在模型配置中标记 `visual = true`。
- `visual.max_image_num` 至少为 `1`。

`auto` 下只要候选模型中包含非视觉模型，就会关闭 Planner 图片输入。`text` 或图片额度为零时，工具仍生成 PNG、附加图片，但结果会明确提示 Planner 当前无法读取图片；不会把图像内容伪装成已经看过的文本。`multimodal` 的模型配置不匹配会明确报错。此功能不自动修改任何现用配置。

沿用现有架构：工具媒体供 Planner 使用，Replyer 不直接接收工具媒体；Planner 可把观察到的内容用于回复指导，也可直接引用媒体索引发图。

## 创建示例

调用 `create_3d_model`：

```json
{
  "name": "小房子",
  "parts": [
    {
      "name": "墙体",
      "primitive": "box",
      "size": [2, 2, 1.5],
      "position": [0, 0, 0.75],
      "color": "#E5D3B3"
    },
    {
      "name": "屋顶",
      "primitive": "cone",
      "radius": 1.6,
      "height": 1.2,
      "position": [0, 0, 2.1],
      "color": "#457BBA"
    },
    {
      "name": "门",
      "primitive": "box",
      "size": [0.5, 0.08, 0.9],
      "position": [0, -1.02, 0.45],
      "color": "#71523A"
    }
  ]
}
```

坐标为右手系，Z 轴向上。长度单位自定，旋转单位为度。几何体初始包围盒中心在原点；创建时先局部缩放，按 X、Y、Z 顺序旋转，再平移到 `position`。

| `primitive` | 尺寸参数 |
| --- | --- |
| `box` | `size: [x, y, z]`，默认 `[1, 1, 1]` |
| `sphere` | `radius`，默认 `0.5` |
| `cylinder` / `cone` | `radius` 默认 `0.5`，`height` 默认 `1`，`segments` 默认 `32` |
| `torus` | 主半径 `radius` 默认 `0.5`，管半径 `tube_radius` 默认 `0.15`，主环分段 `segments` 默认 `32` |

所有部件支持 `position`、`rotation`、`scale`、`color`。颜色为 `#RRGGBB`，默认 `#7C9BC0`；缩放必须为正数。圆环管半径必须小于主半径；分段范围为 8 至 64。部件名唯一，后续编辑使用这个名字。

## 检查、编辑与渲染示例

以下 `model_id` 使用上一次工具结果返回的实际编号。

查看部件：

```json
{"model_id": "<实际模型编号>"}
```

调用 `edit_3d_model`，将屋顶加宽并改色：

```json
{
  "model_id": "<实际模型编号>",
  "operations": [
    {"op": "transform", "target": "屋顶", "scale": [1.2, 1.2, 1]},
    {"op": "color", "target": "屋顶", "color": "#C75249"}
  ]
}
```

编辑的变换是相对变换：绕所选部件当前包围盒中心缩放、旋转，再按 `position` 平移。`target: "*"` 可整体变换或改色；整体旋转共享整个模型的中心，不是各部件各自旋转。`add` 使用 `part` 对象，与创建时部件结构一致；`remove` 指定单个部件名。操作依次执行，每一步均须保留至少一个有效部件。

编辑会返回**新编号**及 `parent_model_id`；后续查看、渲染必须使用新编号才能看到修改。

调用 `render_3d_model`：

```json
{
  "model_id": "<编辑后的实际模型编号>",
  "width": 640,
  "height": 480,
  "azimuth": -90,
  "elevation": 25,
  "background": "#F1F5F9"
}
```

相机采用正交投影并自动取景。方位角从 +X 朝 +Y 增加，仰角范围为 -90 至 90；90 为顶视图，-90 为底视图。默认方位角 45、仰角 30。预览使用不透明面颜色、环境光与漫反射，逐像素深度缓冲处理遮挡。

## 导入已有模型

由本机操作者把模型放到：

```text
data/3d_models/<当前真实聊天流 session_id>/imports/
```

目录不存在时创建该目录。创建或检查模型的结果会返回 `import_directory`。随后调用 `inspect_3d_model`：

```json
{"source_file": "existing_model.glb"}
```

`source_file` 相对于该聊天流的 `imports` 目录，不接受任意绝对路径、目录穿越或远程 URL。`model_id` 与 `source_file` 必须二选一。导入后会保存独立模型版本，返回可编辑的部件名称。

- 支持 OBJ、STL、PLY 和 GLB 2.0 静态三角网格。场景实例和节点变换会保留为各自的部件。
- OBJ 首版支持几何与顶点色，不解析 MTL 或外部贴图；含 `mtllib` / `usemtl` 会明确拒绝。
- GLB 必须自包含，不支持图片贴图、透明、骨骼、动画、形变目标和需要扩展解码的网格。纯色材质转换为网格颜色。
- 保留输入坐标，不自动推测上方向或单位；例如 Y-up 模型可导入后整体绕 X 轴旋转 90 度。
- 首版没有自动下载聊天附件或远程模型的功能，需要先把文件放入导入目录。

## 保存与限制

模型保存于 `data/3d_models/<真实聊天流 ID>/models/<model_id>/`，其中 `scene.json` 为可再次编辑的内部场景，`model.glb` 保留部件和颜色，`model.stl` 仅保留几何。预览位于同一聊天流的 `renders/`。模型编号限定在当前聊天流内，其他聊天流无法凭编号读取；文件不会自动清理，需按实际磁盘空间管理。

- 最多 64 个部件、30,000 个三角面、60,000 个顶点，单次最多 64 项编辑。
- 导入文件不超过 16 MiB，内部场景不超过 32 MiB；PNG 宽高各为 128 至 1024。渲染累计三角形屏幕包围盒不超过 1 亿像素，重叠过多时明确提示降低分辨率或简化模型。
- 对尺寸、非有限坐标、退化面、路径和资源规模做运行时校验；GLB 在解码前按共享引用和场景实例累计规模，避免小文件放大加载内存。
- 导入模型的顶点色在编辑后保留；GLB 导出拆分必要的颜色边界顶点，避免硬面颜色被平均，这些顶点同样计入规模上限。CPU 预览使用三角形平均色。
- GLB/STL 使用单精度顶点；坐标太大、细节太小导致明显量化失真或三角面塌缩时，工具拒绝发布模型，并提示移近原点或放大细节。
- 建模、导入导出与渲染整体在线程中执行，不在 bot 事件循环中直接执行同步工作。
- 首版是组合网格与基础部件编辑，未提供布尔运算、雕刻、骨骼、贴图编辑或照片级渲染。组合部件不会自动布尔融合，导出 STL 不代表通过了 3D 打印可用性检查。
- 工具返回模型文件的本地路径；首版不自动向聊天平台发送 GLB/STL 附件。
