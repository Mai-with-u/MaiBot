# 多 Bot 宿主

MaiBot 的唯一启动入口是宿主（Host）。宿主管理一个工作区内的若干 Bot：每个 Bot 是一个独立的 Worker 进程、一个独立的目录；宿主负责登记、启停、对外 HTTP 和登录。

## 工作区布局

工作区就是实例目录（源码部署为仓库目录，安装版为 `maibot run --directory` 指定的目录）。

```
<工作区>/
  host/
    registry.sqlite3     Bot 登记表
    config.toml          宿主配置：对外地址、Cookie
    model_catalog.toml   共享供应商、API Key、模型与联网服务目录（启动时自动迁移创建）
    webui.json           WebUI 登录凭据
    sessions.sqlite3     登录会话摘要与到期时间
    run.lock             宿主运行租约
    control.json         控制通道地址与凭据（宿主运行期间存在）
    migrations/          adopt --mode move 的步骤日志
  bots/<bot_id>/         宿主创建的 Bot（owned）
    config/ data/ logs/ plugins/ temp/
```

固定密码下的 WebUI 登录会话有效期为 8 小时，宿主重启后仍可使用原 Cookie 自动进入，重启不延长有效期。浏览器仅保存随机票号，数据库只保存绑定当前密码的票号摘要；退出登录撤销当前会话，修改或重置密码撤销旧会话。临时密码和一分钟单次登录链接仍在宿主重启后失效。首次启用会话持久化时，需要重新登录一次。

首次启动时宿主按目录内容决定布局，之后以注册表为准：

| 首次启动时的目录 | 判定 | 动作 |
|---|---|---|
| 已有 `config/bot_config.toml` | 旧用户 | 把工作区根目录原地登记为 Bot（`owned=0`），不移动、不复制、不转换任何数据；从其配置生成 `host/config.toml`，沿用其 WebUI 密码；把内置插件配置复制到 `config/builtin_plugins/` |
| 其他 | 新用户 | 在 `bots/<id>/` 下创建第一个 Bot（`owned=1`） |

`owned=0` 的目录宿主永不删除、移动或改写目录结构，只负责启动它。

## 进程结构

```
Host ──(Job Object / 进程组)──> Worker ──> 插件 Runner
```

- 宿主直接监管 Worker；没有中间的 Runner 层。Worker 以退出码 42 请求重启，由宿主重新拉起。
- Worker 持有 `<bot>/temp/instance.lock`，同一目录不会被两个宿主同时运行。
- 宿主与 Worker 的契约是一个 JSON 环境变量 `MAIBOT_RUNTIME_CONTEXT`（见 `src/common/runtime_context.py`），外加 `MAIBOT_INSTANCE_DIR`。Worker 没有该契约时拒绝启动。

## 通信

| 通道 | 方式 |
|---|---|
| 浏览器 → 宿主 | TCP，地址来自 `host/config.toml` |
| 宿主 → Bot 业务 HTTP / WebSocket | Windows Named Pipe / POSIX UDS，地址每次启动随机生成 |
| CLI → 宿主控制通道 | Named Pipe / UDS，地址与凭据在 `host/control.json` |
| Worker → 宿主状态 | Worker 原子写入 `<bot>/temp/host-status.json` |
| 外部适配器 → 宿主 → Bot（maim_message） | 宿主同一 HTTP 端口，通过带 Bot ID 的路径转发到该 Bot 的 IPC 通道 |

Bot 的 HTTP 服务只监听宿主分配的 IPC 地址，因此 Bot 信任该通道上的请求，不再校验自身 WebUI 凭据；登录只发生在宿主。文件传输的公开地址统一为 `/api/files/bots/<bot_id>/transfers/<token>`。

## 公共配置与独立配置

`host/config.toml` 管理唯一的宿主监听地址、登录 Cookie 和公开访问地址。`[webui].public_base_url` 指定外部可访问的 HTTP(S) 地址，用于生成所有 Bot 的文件链接；留空时使用宿主本地监听地址。经过反向代理或供远程访问时应显式填写此项。

打开工作区时，宿主自动汇总已初始化 Bot 的旧 `files.transfer_base_url`，迁入公共地址；已启用的旧 WSS 证书和私钥迁入 `[webui].ssl_certfile`、`ssl_keyfile`，相对路径按原 Bot 目录转为绝对路径。证书与私钥通过加载校验后，宿主统一使用 HTTPS/WSS（WebUI 地址也变为 HTTPS）。多个 Bot 或现有宿主配置的值不一致时明确报错，不选择默认 Bot、不覆盖已有值；需统一冲突值后重试。

迁移先校验所有来源，再原子写入宿主配置，最后清理 Bot 的旧公开地址、消息监听和 TLS 字段。每个改写文件先以原始字节备份到同目录的 `old/`；迁移中断可再次运行。迁移不会修改外部适配器地址，也不会自动合并模型密钥。

`host/model_catalog.toml` 是供应商、API Key、模型及联网服务定义的唯一配置来源，格式版本为 `3.0.0`。各 Bot 的 `model_config.toml` 只保存任务模型与联网服务选择、任务参数和联网预览长度等独立设置。模型页面直接编辑公共定义，“任务配置”仍作用于当前 Bot；没有共享开关、本地覆盖或手动导入流程。Bot 管理页只负责实例管理；程序更新位于侧边栏和 WebUI 通用设置，依赖检查位于插件页。

首次打开旧单实例工作区时，自动完整迁移供应商和模型定义，保留额外参数，备份原文件后清除实例内的定义。已存在多个实例时，相同定义合并，不同的同名定义按 Bot ID 重命名并同步调整任务引用。新工作区的默认模型直接写入公共目录；后续新建 Bot 只生成独立任务配置。迁移可重复运行，公共目录和实例配置通过带恢复日志的文件事务提交，中断时先恢复原文件再重新迁移。

公共模型保存会校验所有 Bot 的引用，不能删除其他 Bot 正在使用的模型或联网服务；过期编辑需重新加载。公共目录变化由各 Bot 的配置监视器重新加载，配置升级和任务副本切换不会重新产生本地模型定义。副本仅保存当前 Bot 的任务等独立设置。

网络监听、公共访问地址、HTTPS 和访问防护在“麦麦设置 → 公共设置”中管理，保存到 `host/config.toml`，重启宿主后生效；该入口不要求 Bot 正在运行。

`bot_config.toml` 中的人格、聊天行为、权限、插件行为和终端输入开关仍由每个 Bot 独立管理。这些设置即使当前相同，也不属于必须统一的宿主资源。

## maim_message 接入

适配器连接宿主的同一端口，使用完整 Bot ID 明确目标：

- 经典协议：`ws://<宿主地址>:<宿主端口>/maim/<bot_id>/ws`。
- 新 API 协议：`ws://<宿主地址>:<宿主端口>/maim/<bot_id>/api`，目标 Bot 还需启用 `enable_api_server`。

连接始终归属路径中的 Bot。未知或未就绪的 Bot 会拒绝连接，不会改连其他 Bot。经典协议使用该 Bot 的 `maim_message.auth_token`，新 API 使用 `api_server_allowed_api_keys`；空凭据列表拒绝全部连接。协议凭据独立于浏览器登录，按客户端协议发送 Token 或 API Key。

Bot 不再监听独立 TCP 端口，原来的端口、监听地址及 Bot 侧 TLS 配置已移除。旧的根路径 `/ws`、`/api` 和旧端口均不兼容，必须修改适配器地址。需要 WSS 时，可配置宿主的证书和私钥，或在宿主前配置支持 WebSocket 的 HTTPS 反向代理。

## 生命周期

注册表为每个 Bot 记录期望状态 `desired_state`（running / stopped）。宿主启动时按期望状态逐个启动 Bot：前一个就绪或失败后再启动下一个，避免多个大数据量 Bot 同时迁移。

| 状态 | 含义 |
|---|---|
| `starting` | 进程已启动，尚未就绪 |
| `migrating` | Worker 正在执行数据迁移，附带进度 |
| `running` | Worker 报告就绪，HTTP 可用 |
| `stopping` / `stopped` | 正在停止 / 已按请求停止 |
| `failed` | 启动失败或异常退出 |
| `crash_loop` | 就绪后反复崩溃，已停止自动重启 |

- 就绪后异常退出：按指数退避（1s 起，最长 5 分钟）自动重启；10 分钟内崩溃 5 次进入 `crash_loop`。
- 就绪前失败（配置错误、迁移失败）：直接 `failed`，不自动重试，避免对大数据反复执行失败的迁移。

## 旧数据迁移

旧数据永不自动迁移。用户可手动执行：

```bash
maibot host adopt --directory <工作区> --from <旧实例目录> --mode register
maibot host adopt --directory <工作区> --from <旧实例目录> --mode move
maibot host adopt --directory <工作区> --undo <bot_id>
```

- `register`：只登记路径（`owned=0`），零成本。
- `move`：仅限同一文件系统内重命名到 `bots/<id>/`；跨盘直接拒绝。需取得旧实例的实例锁，步骤记录在 `host/migrations/<bot_id>.json`，中断后重新执行同一命令即可续上；完成后旧位置留下 `MOVED_TO_WORKSPACE.txt`，在旧位置启动会被拒绝并提示新位置。
- `--undo`：撤销 `move`（重命名回原位置）或 `register`（删除登记）。
- 两种模式都不做数据格式转换；格式迁移在 Bot 首次启动时照常执行，并显示为 `migrating`。

## 终端输入

交互终端启动宿主时，仅一个 Bot 开启终端输入则自动选中；多个 Bot 开启时使用 `/bots` 查看名称、ID 和状态，再用 `/use 名称或ID前缀` 选择目标。全部 Bot 关闭终端输入时不创建输入界面。提示符仅在输入文字时显示当前 Bot，空闲时隐藏；终端选择独立于 WebUI。名称或 ID 前缀不唯一时拒绝切换。

目标 Bot 必须已就绪并开启 `debug.enable_console_input`。普通文本及 `/pm`、`/offline` 等命令沿用本地操作员消息链，回复通过现有宿主日志转发显示。支持 Tab 补全命令和真实聊天名，以及上下键输入历史；`/host-help` 查看宿主指令，`/help` 查看 Bot 指令。

`exit()` 或 EOF 只关闭输入，Bot 继续运行；Ctrl+C 关闭宿主。非交互启动不读取 stdin。目标停止或请求失败会明确报错，不自动选择其他 Bot，也不自动重发管理命令。输入使用专用 IPC 路径，浏览器代理不能访问；Worker 不创建终端，消息在 Bot 主循环执行。

## 程序更新

宿主首页提供检查更新和确认更新。源码部署沿用官方分支快进更新；uv tool 安装沿用正式版本更新。未提交的代码修改、分支分叉或同一 Python 环境中其他运行中的工作区会阻止更新。操作只应用界面确认的目标提交或版本，不追随检查后出现的新版本。

登记请求并通过预检后，宿主停止全部 Bot，保留登记的期望状态，再关闭 HTTP 和控制通道。宿主进程替换为只加载标准库的更新进程，完成代码和依赖更新后再以新解释器启动宿主。预检失败不打断 Bot；停止失败取消待执行请求；更新失败沿用原更新器的回滚，回滚失败则停止并保留诊断，不在未知环境中启动 Bot。管理页显示最近结果。源码开发模式下自行构建的前端仍按原开发流程管理。

## Bot 重命名、克隆与删除

- 重命名只改变宿主显示名称，不改变 Bot ID、目录或人格昵称。
- 模板克隆暂时停止源 Bot，复制 `config/` 和 `plugins/`，完成或失败后按源 Bot 的期望状态恢复。新 Bot 使用新 ID，默认停止，不复制 `data/`、日志、临时文件、配置备份、Git 历史或虚拟环境。配置中的账号与密钥会复制，启动前需调整，避免重复连接同一账号。
- 删除宿主管理的 Bot 会先停止进程，将整个目录移到 `host/archives/<bot_id>/instance`，保存登记信息后移除活动登记。目录移动后中断，可在下次打开工作区时完成移除登记。
- 原地登记的旧 Bot 和外部目录只停止并移除登记，目录原地保留。归档记录保存在 `host/archives/<bot_id>/record.json`。需要恢复时，可使用 `maibot host adopt --mode register --from <保留目录>` 重新登记。

## 插件依赖与登录边界

所有 Bot 共用一个 Python 环境。启动前宿主自动读取所有已初始化 Bot 的已启用插件的完整依赖声明，包含已安装的包，保留 Bot 与插件来源。运行中安装、启用或变更插件时，Worker 经本机控制通道提交准备请求；宿主回执后独立执行维护，Worker 不导入缺依赖的插件，也不直接修改环境。

声明与当前安装版本不兼容时直接报告；有缺失包时，将完整声明、主程序依赖和当前环境版本一起交给安装器做 dry-run 联合解析。解析通过才停止 Bot，停止后重读声明，确认未变化才安装；完成后按登记的期望状态恢复。安装器固定已安装版本，不自动升级或降级共享库。准备失败会保留具体错误并阻止相关启动，不在同一声明上自动反复重试；修正声明后重新启动，或在插件页显式重试。插件页的依赖操作用于查看诊断和重试，正常启动无需手动补装。


WebUI 登录、密码、会话有效期、退出以及 WebSocket 会话失效统一由宿主处理。Bot 业务接口只经 IPC 提供，不再生成 WebUI 密码或重复验证 Cookie；前端 WebSocket 直接连接宿主代理，无需先领取临时令牌。maim_message 的协议凭据和文件限时传输凭据仍独立保留。

## 后续阶段

- 真实升级回滚及 HTTPS/WSS 的端到端验收。

A_memorix 的向量重建、模型向量库同步及回填进度已在模型设置的嵌入任务下展示，不属于多实例待实现项。启动时的旧存储格式转换是独立流程（历史 pickle 元数据转为 JSON 等），目前记录日志与迁移结果；`host_service` 的 `migrating` 状态覆盖整个内核初始化，不能直接当成实际格式迁移进度，更不能据此将整个 Bot 标记为迁移中。

联网服务的地址、API Key 和协议参数统一保存到公共目录。旧 `web.services` 自动迁入后清除本地副本；同名不同定义保留并同步调整各 Bot 的任务引用。MCP 服务的 `server_ref` 引用各 Bot 自己管理的 MCP 连接，服务共享不会复制或启动 MCP 连接。

## 数据导入与导出

数据传输由宿主提供，目标 Bot 停止时仍可使用。执行前停止目标进程并持有实例进程锁，完成后按原期望状态恢复；上传、压缩和磁盘事务不占用 WebUI 事件循环。任务记录、下载文件和临时目录按 Bot ID 隔离，切换 Bot 不会沿用前一个 Bot 的任务。

支持 1.3.19 的版本 1 数据包。导入仅覆盖所选分类中包内提供的文件，不删除目标实例的其他普通文件；替换 SQLite 数据库时清除目标旧库的 WAL、SHM 和 journal，避免旧事务污染新库。路径越界、符号链接及重复路径会拒绝。导入前备份被覆盖文件到目标 Bot 的 `temp/data-import/<事务 ID>/backup/`，同目录的 `backup-manifest.json` 记录原路径；失败按事务日志回滚，进程中断后下次打开工作区先恢复未完成事务。

导出配置包含当前 Bot 使用的模型、供应商和联网服务定义。导入旧配置时，定义合入公共模型目录；同名但不同的定义保留原公共项，为导入项另取名称并修改当前 Bot 的任务引用，其他 Bot 的引用不变。旧包中的网络地址和缓存、日志保留策略不会覆盖现有宿主公共配置。配置历史备份不进入导出包，也不从旧包恢复。

导入插件后恢复运行仍执行宿主统一依赖检查；如需补装公共依赖，遵循现有宿主维护流程。

## 公共缓存与日志保留策略

在麦麦设置的公共设置中管理缓存清理与日志保留，保存到 `host/config.toml` 的 `retention.images`、`retention.emoji` 和 `retention.logs`。共享的是清理开关、检查间隔、保留天数、日志文件大小和数量，图片、表情包、识别记录及日志文件仍保存在各 Bot 自己的目录。

首次迁移读取旧 Bot 配置：任一旧实例关闭某类缓存清理则公共策略保持关闭；间隔、天数、大小及数量取旧值中的最大值，避免迁移后更激进地删除数据。已有公共策略时以公共策略为准。原配置备份后删除 Bot 内重复字段，重复启动不会重复迁移；新建实例直接使用公共策略。公共策略变更由配置监视器加载，缓存清理和日志清理在各自后续清理周期生效，日志轮转使用更新后的大小和数量限制。

## 一次性工作区配置迁移

未发布的公共模型 1.0.0、2.0.0 格式不属于支持的历史版本；只支持最终公共目录格式及已发布的单实例配置（含 MaiBot 1.3.19）。网络与访问、缓存和日志保留、供应商/模型/联网服务在同一迁移计划中完成校验，再统一备份与事务提交；任一校验失败不写入目标配置，写入失败回滚整批文件。

迁移备份统一放在 `host/backups/workspace-migration-<事务 ID>/`，`manifest.json` 对应原文件绝对路径与备份文件名，原内容保留换行。已经完成迁移的配置再次启动不会重新提交或生成备份。运行中的宿主持有启动租约，另一个入口不能在其运行期间执行恢复和迁移。

新工作区及新建 Bot 使用独立初始化入口直接生成最终配置：公共默认值只在首次创建时写入，Bot 文件不落地公共供应商、模型、联网服务及清理策略的重复定义，也不调用旧配置迁移。导入 1.3.19 数据包复用相同字段清理与模型合并函数，但仍遵守导入自身的实例隔离与备份事务。
