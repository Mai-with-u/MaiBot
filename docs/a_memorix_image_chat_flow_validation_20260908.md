# 图片记忆真实聊天业务验证报告

测试日期：2026-09-08。

> 当前进展：2026-09-12已补齐五项管理与恢复功能，并完成生产UI组件浏览器交互、真实模型变体测试和自主Planner到正常CLI回复的闭环。当前结果及尚未覆盖范围见 [最新验证报告](a_memorix_image_extension_validation_20260912.md)，本文件保留当时观察。

> 后续修正：已按用户意见移除图片自动注入的独立等待预算及 `online_wait_ms` 配置，沿用记忆服务默认120秒和模型请求自身的超时机制，不再在注入层将超时转换为空结果。新增的延迟召回与超时传播回归共2项通过。下文180毫秒和测试进程5000毫秒设置描述的是本轮真实测试发生时的代码状态，不是当前配置要求；当前只需配置图片模型和请求协议。

## 1. 当前结论

本轮在真实注册的模拟聊天流上，使用实际消息数据库、A_Memorix SDK、后台任务和外部模型，跑通了图片入库、视觉相似检索、摘要自动关联、规划器上下文注入、查询工具、图片描述补偿、记忆修正以及记忆包迁移和卸载。测试中发现的代码问题已修复，并进行了回归验证。

这支持图片记忆主要业务链路在本次配置和样本下可用，不能推导为所有场景均无问题。平台适配器收发、完整自主规划循环和浏览器交互没有在本轮实测；实际配置中的图片模型任务仍为空，测试进程临时绑定了可用模型。当前图片检索沿用记忆服务默认120秒等待和模型请求自身的超时机制。

本报告补充并更新此前 `a_memorix_image_business_test_20260908.md` 的结果。此前的失败记录仍保留，不通过修改相似度阈值或忽略失败来判定通过。

## 2. 测试环境与真实性

通过 `chat_manager.get_or_create_session` 注册两个独立聊天流，使用真实 `SessionMessage`、图片和转发组件构造消息，并调用消息持久化、记忆自动化入口。聊天流归属来自注册结果，没有自行计算替代ID。测试场景为用户给图片命名为星团，说明它将用于下周六的读书会海报，再发送图片变体询问名称和用途。

图片使用仓库公开素材及其缩放、JPEG重编码版本。嵌入通过宿主、EmbeddingService和现有请求客户端调用实际Provider，返回2048维向量；摘要、VLM描述和修正计划也由实际模型生成，没有注入预制向量或伪造模型回答。摘要与图片的初始关联由模型输出的 `facts.image_evidence` 建立，未手工插入该关联。

消息数据库、记忆数据库和记忆包使用 `.codex/image_business_20260908/` 下的独立实验目录。宿主仍会初始化日志、模型请求统计等设施，消息图片缓存还会写入固定的 `data/images`，所以不是完全无宿主副作用的沙箱。没有向真实群聊、私聊或其他人发送消息。

测试入口是本地实验文件 `chat_flow.py`，扩展用例为 `extended.py`、`vlm_flow.py`、`final_checks.py` 和 `drain_checks.py`，均位于上述实验目录。实验文件及其数据不应进入共享历史。

## 3. 进程内配置

| 项目 | 本次设置及原因 |
| --- | --- |
| 图片模型 | 从已配置的 `jina-embeddings-v4` 克隆独立别名，绑定 `image_embedding` 任务 |
| 请求协议 | `image_embedding_input = [{ image = "{base64}" }]`，使用Moark的image字段和原始Base64 |
| 在线等待 | `online_wait_ms = 5000`，本次真实查询约需秒级时间；默认180ms不能覆盖该延迟 |
| 摘要模型 | 进程内将utils候选限制到本次能完成请求的模型，避免随机候选错误干扰定位 |
| 修正计划复测 | 输出预算1800，硬超时120秒；此前90秒请求超时如实保留 |
| 记忆作用域 | 默认关闭全局共享；共享组和全局包可见性在对应用例内单独启用 |
| 图片指纹 | 请求协议摘要参与指纹；跨实例测试另外改变预处理版本，以验证不兼容向量重建 |

没有编辑实际 `bot_config.toml` 或 `model_config.toml`。投入实际聊天前需要配置图片模型任务和显式输入协议，检索沿用记忆服务默认120秒等待和模型请求自身的超时机制，无须配置独立在线等待预算；本轮成功不代表空图片任务配置下可直接使用。

此前独立素材测试还记录了128像素缩放版相似度0.913822、JPEG质量65版本0.992889，其他两张候选约0.3564至0.4542。它们与本轮组合变体不同，不应混为一次测量。三个原始素材远不足以估计总体准确率、误报率或阈值最优值。

## 5. 图片描述、回填及生命周期

| 流程 | 结果与证据 |
| --- | --- |
| 嵌套转发图片 | 两次同图出现保存为不同组件路径 `0.0.0`、`0.0.1` |
| 重复历史回填 | 两条路径及出现数量保持一致，没有因为重复回填生成重复出现 |
| 真实VLM描述 | 加载正常prompt启动环境后，实际模型返回人物外观描述 |
| 描述后到 | 已有图片收到描述后触发持久化摘要补偿 |
| 描述先到 | 先保存真实VLM描述，再接入对应图片变体；待绑定记录从1变为0 |
| 补偿跨进程恢复 | 中途关闭后重新启动继续处理，最终5项补偿任务均为done |
| 人工说明修正 | 创建version 2并替代旧说明，当前查询只返回新版本 |
| 图片删除 | 删除最后引用后释放资产和向量，统计同步下降 |
| 删除后同图重发 | 重新入库、重新排队和向量恢复成功，任务processed为1 |
| 模糊记忆修正 | 真实模型生成将下周六改为下周日的计划，执行成功，随后回滚至rolled_back |

先到描述用例复用了同一原图已经生成的真实VLM描述，绑定目标为它的缩放变体，没有对该变体另发一次VLM请求。恢复验证覆盖正常关闭后再次启动，不等同于断电或强杀下的全部崩溃一致性验证。

## 7. 本轮发现并修复的问题

| 问题 | 修改及验证 |
| --- | --- |
| 已有图片资产但无向量时，新图注入为空 | 查询按content_hash找到资产后，缺向量时读取真实图片进行在线嵌入；真实未索引用例通过 |
| 删除后重发不能重新建立向量 | 删除时标记嵌入失效；已终止任务在缺少ready向量时重新排队；发布时恢复向量删除标记；真实重发和回归用例通过 |
| 卸载后仍统计已删除向量 | 统计关联有效资产和出现记录，避免将已删除对象计入有效状态；目标实例卸载后全零 |
| Windows完整包安装报WinError 5 | 图快照写入唯一的未发布generation目录，完成后切换指针，避免重命名非空目录；混合包导入和已有持久化回归通过 |
| 不同图片请求协议共用指纹 | 将输入模板、请求体及相关参数摘要传递到图片指纹，避免错误协议的向量空间被直接复用 |
| 未声明图片协议时隐式发送字符串 | 请求客户端改为要求显式图片输入模板或请求体，缺配置在网络请求前报错 |
| 失败的向量包导入可能误删既有向量 | 回滚只清理本次新加入的向量，不把导入前已存在的有效向量纳入删除集合；新增回归用例通过 |

A_Memorix内部修改是本轮本地修复，尚未提交；按MODIFICATION_POLICY，其实现归属仍需在上游MaiBot_branch维护，不能长期形成分叉。

## 8. 失败记录与最终队列状态

首轮测试观察到Provider的503、502、429以及修正计划90秒超时。调整测试候选和预算后完成对应业务，但这些复测不消除外部服务可用性风险。VLM首轮还遇到实验入口未加载prompt的问题，补齐正常启动步骤后成功；这项属于测试环境问题，没有修改生产prompt内容来规避。

最终源实例：资产3、出现6、说明17、关联2、就绪图片向量3。图片任务待处理0、失败0，描述补偿待处理0、失败0、未绑定0；补偿表中5条记录全部done。目标实例完成重建后卸载，相关统计全部为0。

回归验证包括此前较广的186项测试通过、最终向量导入回滚修复后的图片运行时14项通过，二者有重叠，不能相加为200个独立测试。针对本轮改动文件的Ruff检查和git diff --check通过。本轮没有重新运行前端构建；此前完整前端构建存在其他测试文件的类型错误，不能将后端测试通过描述成整个工作区构建通过。
