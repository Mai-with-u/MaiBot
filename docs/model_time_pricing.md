# 模型分时价格

在 WebUI 的「模型管理 → 模型设置」中添加或编辑模型，保留默认输入、输出价格，并按需添加「分时价格」。开启模型的缓存计费后，可以同时设置默认和各时段的缓存命中输入价格。

## 计价规则

- 所有价格单位均为元 / 百万 token，仅用于 MaiBot 的费用统计，不会修改服务商账单或请求参数。
- 时段每天重复，按 **MaiBot 服务器的本地时区** 匹配，不使用浏览器所在时区。服务器时区应与所填服务商时段一致。
- 根据最终成功的请求尝试的开始时间，统一选择输入、输出、缓存三项价格。跨时段返回的请求不拆分计价；重试或切换模型后，以成功尝试的开始时间为准。
- 时间格式为 `HH:MM`，范围为 `00:00` 至 `23:59`。包含开始时刻，不包含结束时刻。例如 `08:00–12:00` 不包含 `12:00`。
- 结束时间早于开始时间表示跨午夜，例如 `23:00–07:00`。开始与结束不能相同，相邻时段允许，重叠时段会拒绝保存。
- 未匹配任何时段时使用模型默认价格。没有配置时段的旧模型保持原有计价方式。
- 价格必须为有限的非负数，`0` 表示免费。每个时段都应填写完整的三项价格；缓存单价只在模型 `cache=true` 时参与计费，关闭开关不会删除已填写的缓存价格。
- 缓存价格指服务商返回的缓存命中输入 token 单价。缓存未命中按普通输入单价计算；不包含独立的缓存写入、存储计费。
- 历史用量记录保留原费用，修改价格不会重算历史账单。

## TOML 示例

以下为单个模型配置示例，提供商名称需对应已有的 `api_providers`。价格仅用于演示，并非服务商报价。

```toml
[[models]]
name = "example-model"
model_identifier = "example-model-id"
api_provider = "example-provider"
price_in = 2.0
price_out = 8.0
cache = true
cache_price_in = 0.5
price_periods = [
    { start_time = "23:00", end_time = "07:00", price_in = 1.0, price_out = 4.0, cache_price_in = 0.1 },
    { start_time = "12:00", end_time = "14:00", price_in = 1.5, price_out = 6.0, cache_price_in = 0.25 },
]
```

上述模型在每天 `23:00` 至次日 `07:00` 使用第一组价格，在 `12:00` 至 `14:00` 使用第二组价格，其他时间使用默认价格。清空 `price_periods` 即恢复全天使用默认价格。
