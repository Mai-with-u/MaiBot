# 图片记忆五项扩展与真实流程验证

日期：2026-09-12。范围：用户本轮指定的历史回填、任务诊断、记忆包图片管理、发布中断恢复、WebUI相似图片检索，以及完成后的验证推进。

## 1. 当前结论

五项功能均已接入当前工作区，验证过程中发现的重复认知、导出引用不完整、空结果统计缺失和后台量化训练未触发等问题已修复。真实外部模型、数据库、记忆服务、摘要、Planner和项目正常CLI回复路径已经跑通。WebUI生产组件也通过真实鉴权和实际后端完成了主要交互。

这些结果支持本次配置和样本下的业务可用性，不等于所有样本都能命中，或者原始计划的所有消费者与部署环境都已验证。真实模型测试保留了默认阈值下的一次漏召回，工程测试也保留了量化排名偏差。没有为了验收调低阈值、修改标签或删掉失败样本。

## 2. 实现与操作入口

### 2.1 历史回填预览与分类

在长期记忆的图片页点击预览历史回填。前端每批读取100条历史消息，固定第一批取得的消息ID上界，完整预览后才开放执行按钮。执行忽略预览后新到的消息，并重新检查图片和来源。可在当前批次结束后停止，随后重新预览并再次执行。

接口是 `POST /api/webui/memory/images/backfill`，查询参数包括 `preview`、`limit`、`before_id` 和 `upper_id`。预览不写入图片记忆，返回消息级计数和图片组件级分类：

| 分类 | 含义 |
| --- | --- |
| ready | 图片与真实来源可读取，允许执行 |
| processed | 本次执行成功，包括幂等重放 |
| missing_source | 结构化消息或必要来源字段无法读取 |
| missing_chat | 找不到真实注册的聊天流 |
| missing_file | 历史图片二进制已不可读取 |
| invalid_image | 图片内容、大小或格式未通过资产检查 |
| write_failed | 前置检查通过，但实际写入返回错误 |

同一消息中的有效图片不会被无效兄弟组件阻止。`component_paths`过滤保留原始嵌套路径，不重排图片身份。界面累计展示全部分类数量，并保留最近200条逐图详情，避免历史数据量直接撑大页面。

重复回填按照出现记录的外部引用去重。用户原始说明和模型描述也按同一出现记录、来源类型和文本去重，检查包含已被替代的版本，因此再次回填不会恢复已经修正的旧认知。此修复不会擅自删除旧版本此前已经积累的重复行。

### 2.2 图片任务诊断与统计

`GET /api/webui/memory/image-jobs`按状态筛选并分页返回嵌入任务与描述补偿任务，包含任务种类、资产、执行次数、最后错误、更新时间和租约期限。WebUI每页25项，可查看失败原因及任务流转状态。

状态接口增加当前实际指纹下的索引进度、资产字节总量和启动恢复结果。就绪进度按当前模型计算，不能拿旧模型向量或仅保存的图片充数。检索结果提供范围解析、编码与准备、向量检索、关联展开和总耗时，以及返回关联记录数。已有图片的编码与准备阶段可能主要是本地状态和向量读取，不能将这段时间一律解释为外部HTTP调用耗时。

空范围检索返回零条关联和完整的阶段字段。恢复异常在页面直接提示数量，同时可展开查看具体文件与原因。

### 2.3 记忆包图片管理

记忆包导出范围增加选择图片，通过每页24张缩略图进行多选。携带直接关联知识是明确的勾选项，关闭时只导出所选图片、出现记录和认知；开启时补齐直接关联目标所需的段落与知识，不再沿新增段落收集其他图片。其他导出选择器保持既定范围，范围外关联不写入包。

预览导出内容使用 `POST /bundles/export`的 `preview=true`，复用正式导出的收集和资源读取过程，返回图片、段落、实体、关系、关联数量和未压缩体积，不生成包文件。`include_image_related`决定是否扩展关联知识。正式导出重新读取当前数据，预览不是阻止其他写入的数据库快照。

开启携带关联知识时，无法迁移的悬空目标会明确报错。Episode关联要求完整包；没有来源段落的孤立实体、关系或Episode目前需要先补齐来源知识，不能通过留下缺失目标来伪装导出成功。

安装前使用同一上传接口的 `preview=true`执行包检查，展示文件体积、图片数量、出现和关联数量、资源检查结果、向量兼容性。资源检查先校验完整包，成功后缺失资源数才为0；损坏或缺失时直接展示校验错误，不把局部检查当作完整通过。

安装后分别显示图片内容已安装、当前模型检索就绪或等待构建、模型不可用或功能未启用。已安装列表展示图片数、出现数和当前指纹就绪向量数。模型不可用不再被笼统显示为等待构建。

### 2.4 发布中断与向量恢复

运行时在后台写入任务启动前执行资产核对，以已提交的有效出现记录作为保留依据：

- 文件发布后尚未登记元数据就退出：启动扫描清理资产库生成的无引用文件。
- 资产元数据已登记但出现记录未提交：终止相关无引用任务、标记资产删除并清理文件。
- 临时文件遗留：只清理符合资产库生成规则的临时文件。
- 有有效出现引用：保留文件，并检查文件是否存在及哈希是否一致。
- 引用有效但文件缺失或损坏：保留事实记录、记录具体异常，不能宣称已恢复原始字节。
- SQLite中向量已就绪，但对应磁盘投影缺失：初始化时改回待处理并重新排队。
- 已删除资产仍有旧磁盘向量：初始化时应用删除并持久化清理结果。

核对假设一个运行时拥有一个资产目录，且启动核对发生在写入工作开始前。没有增加多个进程同时写同一目录的协调能力。启动哈希核对需要读取已引用图片，数据量和总字节数会影响启动耗时。

量化索引在后台达到图片配置的样本门槛后训练。此前通用向量库直到万条样本才自动训练，而图片运行时只在重启加载时使用较小门槛；现在新库无需重启即可触发。训练或预热失败明确抛出错误，不隐藏为已就绪。

### 2.5 WebUI相似图片检索

在图片页选择库内图片并发起相似搜索，可调整相似度阈值。结果区展示同图或相似匹配、分数、缩略图、真实聊天名称、认知、关联知识和阶段耗时。后端接口为 `POST /api/webui/memory/images/{asset_id}/search`，支持限定真实聊天流；管理界面默认搜索管理员可管理的全部图片。

本轮入口以库内图片作为查询图，没有增加独立的临时图片上传搜索入口。对话中的新图片查询仍走既有消息与图片记忆接入链路。

## 4. 真实业务验证

### 4.1 环境与隔离

实验使用独立SQLite消息库和A_Memorix目录，放在本地 `.codex/image_business_20260908/`。模型任务只在测试进程中绑定：图片模型为真实 `jina-embeddings-v4`，实际返回2048维，请求使用已验证的Moark图片Base64对象协议；摘要、Planner和回复使用实际配置中的可调用模型。没有替换外部模型返回值或编造搜索命中。

公共素材来自仓库的 `depends-data/maimai.png`、`video.png`、`webui-showcase.jpg`。消息图片构造会通过项目图片管理器写入正常图片缓存，因此隔离的是业务数据库和记忆库，并非完全没有工作区缓存副作用。实验脚本、数据和截图保留在本地实验目录，不进入共享历史。

### 4.2 浏览器与实际API

临时Web服务挂载生产路由，正常保留身份验证；未登录调用返回401，浏览器通过正常登录接口取得会话。前端开发服务使用7999端口。测试页面直接导入实际 `ImagesTab`、`MemoryBundleCard`、组件库和样式，并非模拟页面或虚构响应，但没有覆盖完整主应用的侧边栏导航。

已实际操作：选择图片、搜索、读取关联内容、预览两条历史消息、执行其中一张图片的回填、查看任务、选择图片导出、上传包检查、安装并查看就绪向量。一次缓存搜索返回3张图，原图1.0000、缩放图约0.9381、JPEG变体约0.8799，展开2条关联，总耗时约12.14毫秒。浏览器错误日志为空。

浏览器覆盖的是这批功能主体。随后补充的导出范围预览、显式关联开关、空结果统计和状态文案通过定向回归检查；不把这些后续修改声称为已重复完成浏览器全流程。截图为本地 `ui_verified.png`。测试服务达到本地脚本12分钟生命周期后停止，记录的服务寿命超时不属于检索超时或业务断言失败；临时登录令牌文件已清理。

### 4.3 自主Planner到正常回复

使用项目CLI会话构造入口注册真实聊天流。发送原始图片并告知名称和读书会用途，经过真实摘要生成1条段落及图片关联，再发送缩放JPEG变体询问名称和用途。

第二条消息进入真实 `HeartFCMessageReceiver.process_message`，随后启动实际Heartflow调度和Planner。Planner配置为文本视觉模式，使本轮结果依赖图片记忆注入；Planner自行选择reply工具，真实回复生成器通过项目正常CLI渲染路径输出：

> 星团喵，下周六读书会的海报用的~

记录输出的包装调用了原来的CLI渲染函数，没有替换发送行为。结束时2张资产、2个向量、1条图片关联，嵌入和描述任务均无待处理或失败项。没有向真实QQ、Telegram等第三方聊天发送消息，因此平台网关和外部适配器收发仍未覆盖。

### 4.4 真实图片变体与延迟

三张原图各生成128像素缩放、JPEG质量35、中心保留80%裁剪、亮度60%四种变体，共12次独立查询。观察排名时允许返回全部3个候选，单独按现有默认0.72计算能否被接受，没有改变默认阈值。

| 指标 | 观察值 |
| --- | --- |
| 请求完成 | 12/12 |
| 原图排名第一 | 12/12 |
| 原图达到默认0.72 | 11/12 |
| 未达到阈值的样本 | `webui-showcase.jpg`缩小至128像素，0.629009 |
| 在线总耗时P50 | 2641.54毫秒 |
| 在线总耗时P95 | 6558.23毫秒 |
| 已有向量的并发调度查询 | 30次全部有结果，最大12.16毫秒 |

这里只用了12次在线查询，P95按近邻秩取本组最大值，不能据此推断服务稳定分位延迟。三张图之间的非目标相似度观察到约0.6431，盲目降低阈值可能增加误召回。此样本库也不足以得出普遍Precision、开放集误识率或对象身份判断能力。

缓存查询通过同一事件循环并发调度，不代表长期高并发压测。图片检索仍沿用服务和模型自身超时，没有重新加入独立180毫秒等待限制。

## 5. 限定规模工程验证

另建512张不同静态PNG、2048维确定性合成向量的数据库。32张属于一个小聊天范围，其他480张属于另一个范围。此实验验证存储、索引、范围和恢复，不测量模型识图能力。

| 指标 | 修复后结果 |
| --- | --- |
| 图片写入 | 512张，约5511.24毫秒 |
| 后台索引构建 | 512个，约9488.95毫秒 |
| 不重启时是否训练完成 | 是 |
| 小范围查询 | 32次，每次8个结果，范围泄漏0 |
| 量化Top8相对浮点排序的平均重合率 | 0.95703125 |
| 最低单次Top8重合率 | 0.875 |
| 缓存查询P50 / P95 | 28.205 / 30.63毫秒 |
| 同一出现记录重复写入 | 并发调度32次，仍为512资产、512出现 |
| 重新打开数据库与运行时 | 约1324.90毫秒，512向量就绪，恢复异常0 |

量化索引使用较早批次训练，与收齐512张后一次训练可能出现不同排名偏差。报告保留真实重合率，不将近似索引当作完全等同于浮点排序。资产为8×8小图，这组启动耗时不能代表512张高分辨率图片，更不能代表几十万张图片。

## 7. 后续验证边界

本轮五项功能已经实现，但以下结论仍缺少相应覆盖：生产平台适配器完整收发、完整主应用导航、真实用户的大规模历史库、长期并发写入与删除、多进程共享目录和广泛的真实正负图片集合。512张合成向量测试与三张真实素材的12个变体均不能替代这些验证。

原始总计划中其他消费者，例如人物事实账本独立消费图片证据，不因本轮管理功能完成就自动视为完成。原图已经丢失时也不能靠中断恢复凭空重建；系统明确保留异常供处理。实际默认配置仍需由部署者绑定可用图片模型和协议，本轮只在测试进程完成绑定。
