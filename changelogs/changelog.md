# 更新日志

# [1.3.6] - 2026-10-7

## 主程序

- 长期记忆：重建期间切换嵌入模型时取消旧任务、删除未完成检查点并立即重新构建，复用正常运行的模型指纹规则，避免同维度模型的向量混用。

- 行为学习：移除学习、场景检索、Planner 行为参考、共享配置及 WebUI 管理入口，升级时清理相关数据库表并自动压缩数据库，已完成清理的数据库也会补做一次瘦身。
- 插件 WebUI：上传组件可声明图片边长限制，上传前自动等比例缩小超大图片并将超过20MiB的图片转JPEG压缩，保留本地原文件。
- 插件 WebUI：修复后台轮询清除操作报错，导致训练提交失败提示短暂出现后消失的问题。
- 插件 WebUI：增加按钮弹窗选择、跨页多选与批量操作成功后清空选择能力；自身角色识别插件支持批量身份标注、批量删除及确认后删除全部图片。
- 长期记忆：向量重建逐批保存检查点，重启后继续未完成内容；直接嵌入请求遇到限流和临时服务错误最多尝试三次，统一调度请求沿用原有重试配置，整轮结束后补算失败项，最终仍失败才丢弃本轮构建。
- 长期记忆：模型配置页显示启动向量库同步和更换模型、手动重建的阶段与逐批进度，避免将构建期间的临时降级显示为嵌入服务不可用。
- 模型请求：记忆和表达等文本嵌入请求共享限速，遇到 HTTP 429 时按近期发送速率减半，最多两次；限速等待不计入模型耗时。
- 复古回复：图片放在合并 user 消息中对应历史发言的位置，回复指令保持在末尾；请求预览按内容片段顺序显示文字与图片。
- 复古回复：复用普通上下文的可见文本与图片渲染，修复空白或旧缓存导致正文丢失、引用关系不显示及引用图片描述停留在占位的问题；不再单独截断历史图片描述，视觉输入遵守统一图片数量限制。
- 推理记录：启动图片引用索引只加载实际引用图片的记录，避免将十万份无图片日志的索引全部转换为内存对象。
- 回复工具：将 reply_reference 设为必填参数，缺失、空白或类型错误时要求 Planner 补齐，不再使用分析正文代替。
- 复古回复：过滤历史 Planner 模型输出，保留麦麦实际发送的消息，并在聊天记录中标注自身身份。
- 长期记忆：将嵌入探测的模型身份与维度一并缓存，修复候选模型切换后的指纹错配。
- 人物事实：修复幂等重放时事实与证据正文不一致、空置信度报错及零置信度被覆盖的问题。
- 长期记忆：修复旧人物事实迁移时误标稳定、历史证据漏选和画像分类变更后缓存未失效的问题，事实来源统一记录实际输入的消息。
- 情景记忆：持久化成功但没有情景的分组指纹，避免重复调用模型，输入或模型配置变化时重新生成。
- 表达：修复模型切换期间旧向量结果仍被发布的问题，未使用向量库的文件已缺失时也能完成删除；嵌入任务引用不存在的模型时在配置加载阶段报错。
- 复古回复：直接丢弃历史 assistant 内容与自身回复，不再拼入 replyer 请求。
- 古回复：人设与聊天注意事项合并为首条 system 消息，回复风格保留在原模板位置。
- 消息路由：增加正式 account_id/scope 归属字段，入站消息仅匹配网关已声明的身份，不再登记额外机器人账号；旧归属格式暂时兼容并警告，将在下个版本移除。
- 回复分割：修复 LLM 断句模式忽略回复分割总开关，导致关闭分割后仍调用断句模型并拆分回复的问题。
- 推理记录：模型快照保存和状态更新移至工作线程，避免图片清理占锁时卡住主循环；失败快照写入后保持不变，重试及最终结果以事件追加，WebUI 与回放工具读取时汇总；图片引用索引按新增、删除同步持久化，启动和定期清理不再全量核对日志目录，仅核对引用图片的记录是否已被删除。
- 日志：统一记录推理预览构建、排队、文件读写、锁等待、记录更新与清理耗时；慢操作告警，图片引用全量扫描定期报告进度，便于定位卡顿。
- WebUI：修复系统禁用 IPv6 时把 ::1 地址不可用误报为端口已被占用、导致 WebUI 无法启动的问题，现在会跳过本机不可用的地址。
- 图片上下文：修复手机拍摄的 MPO 照片或 BMP、TIFF 等图片使规划器报「不受支持的图片格式」而中断的问题，现在会把首帧转为 JPEG（带透明信息时为 PNG）。
- 回复工具：修复附带表情的情绪标签以裸文本写入自身历史、被模型模仿进回复正文的问题，表情统一显示为「[表情包: 描述]」。
- 模型请求：修复 OpenAI 兼容接口把多段纯文本消息作为数组发送，导致阿里云百炼等服务返回 400 invalid string 的问题。
- 模型提供商：兼容百炼业务空间专属域名 {WorkspaceId}.{region}.maas.aliyuncs.com，图片嵌入会走百炼原生协议，模型配置页也能识别百炼模板并显示思考开关。

## Webui

- 插件扩展：启用、关闭插件及运行时注册变化时同步刷新顶部 Tab 与侧栏入口，无需手动刷新网页。

- 插件扩展：顶部最多显示两个插件工作区，“更多”入口紧邻标签并适配顶栏主题；管理插件页面支持独立调整顶部 Tab 顺序，立即生效并保存到浏览器。

- 插件扩展：新增经过登录和插件归属校验的多图片上传组件、一次性文件领取凭证及后台任务轮询，文件内容不经过JSON/RPC。

- 麦麦观察：主动 wait 显示「等待(剩余秒数s)」并实时倒计时，启动后和本轮处理结束后统一显示「空闲」。

- 插件更新：更新过程中可点击取消，刷新、关闭或离开页面也会自动终止下载并清理临时文件；已开始的版本替换会安全收尾。

- 插件扩展：新增详情弹窗、折叠容器、表格行选择、选中行操作参数、数组循环与条件显示，Hello World 提供完整示例。
- 插件扩展：图库支持自动排布与列数选择，新增查询分页按钮及可选的表单自动刷新。

- 插件扩展：新增受限的缩略图库组件，支持本地栅格预览、作品信息和安全外链，供 Pixiv 图库侧边栏使用。

- 模型配置：修复编辑后快速切换页面会取消待执行的自动保存、丢失模型列表、功能分配或提供商改动的问题，离开页面时立即提交待保存配置。
- 推理历史：普通记录读取不再争用存储锁或逐文件输出诊断日志，只对慢读取、失败及耗时较长的列表查询告警，避免浏览历史时大量刷日志。
- 插件市场：浏览详情时将安装版本并入顶部信息卡片，左侧完整展示 README 与更新日志，右侧显示统计和基本信息，文档区域统一滚动整个详情页。
- 模型配置：供应商改名时同步迁移已定义模型的供应商引用，保留模型配置与任务分配，避免误触发级联删除。
- 插件市场：缓存首屏与刷新后统一使用市场列表自带的统计快照，推荐抽选在同一浏览器会话内保持一致，减少进入页面后的排名跳动。
- 插件市场：接入下载与点赞的 7 天、30 天飙升排名，仅为前八名显示醒目标签，同一指标优先展示 7 天榜，下载与点赞同时上榜时只显示名次更靠前的一项。
- 插件市场：默认排序为飙升榜前八名提供少量权重，7 天榜加成高于 30 天榜，多个榜单取最高加成。
- 插件市场：卡片右上角以轻量侧线标签显示最近七天的发布或更新，按分钟、小时、天展示距今时间；有标签时替代装饰纹样，无标签时保留纹样。
- MCP 服务：修复列表读取总开关字段错误，导致已开启的服务仍显示「已禁用」的问题。
- 插件详情：左侧 README 随内容自然延伸；右侧上下排列基本信息、市场反馈与更新日志，增加更新日志显示高度，默认展开并使用紧凑字段布局，减少留白。
- 插件详情：隐藏顶部的打开文档与源代码切换按钮。
- 插件设置：注册组件移至设置项底部，重置按钮放在其下方，减少误点击。
- 顶栏：修复搜索面板打开时当前工作区标签的选中高亮消失的问题。

# [1.3.5] - 2026-10-7

## 主程序

- 表达：统一向量库列表、同步状态和删除接口，聚类页面支持查看并清理未使用的模型分组。
- 表达：嵌入模型身份纳入服务地址、有效维度和请求参数，兼容旧索引并自动补建。
- 表达：配置切换后立即刷新嵌入标定并唤醒后台补建，跳过旧配置的扫描等待。
- 修复模型切换后手动重建覆盖旧库、缓存重载丢失模型身份及单池重建后索引未预热的问题，取消同步时等待文件操作完成
- 情景记忆改用段落序号关联内部 hash，允许跳过无关段落与重叠引用，生成失败进入重试而不再合并降级
- WebUI 记忆状态窗口展示已保存的模型向量库，支持删除未使用库并保留记忆内容
- 长期记忆在嵌入模型变化后自动同步向量，按模型保留旧库并通过输入 hash 复用未变化的向量
- 长期记忆：人物事实采用模型提取与分类结果，取消逐字匹配和特殊可信标记准入，恢复旧自动事实的画像分类。
- 图片输入：模型请求内置单边 8000 像素限制，普通超大图等比例缩小，超限长截图分段发送并保留边界重叠。
- 启动：提前启动独立线程中的 WebUI，与插件及其他组件初始化并行，缩短管理页面的等待时间。
- 日志：统一缓存、调度及回复输出格式，表达学习与例行维护细节降为 DEBUG，长入站消息显示预览并保留 DEBUG 全文。
- 回复工具：修复引用机器人自身消息时将机器人误报为收件人。
- 回复工具：通过 attach_pic 发送的图片各自作为独立消息发送，不再与回复文字合并。
- 聊天触发：修复动态模式将过期积压消息计入近期活跃度、导致群聊长时间不启动 Planner 的问题。
- 模型任务分配：聊天回想未配置时使用 fast_model，再继用 utils；表情替换优先使用 emoji，未配置时使用 planner；WebUI 默认显示已配置的高级模型任务。
- 优化插件加载逻辑，减少状态不一致情况。
- 插件更新：其他已安装插件的依赖版本冲突改为提醒，不再阻止安装或更新。

# [1.0.8] - 学习与Maisaka更新 - 2026-6-25

**注意：此版本改动内容较多，请阅读以下说明**

- Q：为什么更新后麦麦说话太多/太少？
- A：1.0.8更新了maisaka的发言机制，可能对于不同的人设会有不同的变化，你可以 1.修改人设或提示词；2.调整回复频率模式 3.调整回复频率数值 来尝试微调

- Q：为什么表达选择使用了“精细”或者“超级精细”模式后，回复变慢？
- A：这是因为这些模式下，Maisaka需要进行更细致的表达分析，使用LLM和嵌入进行计算，你可以使用更快的嵌入模型，并且修改模型配置中的expression_use模型来加快速度。

- Q：为什么麦麦出现了连续回复或者回复自身？
- A：可以尝试 1.修改planner的提示词 2.开启 聊天-标记自身消息 3.避免使用参数量过小的planner模型 4.修改 聊天 - 什么时候发言 - "连续 wait 上限" ，调低该数值可以降低性能较弱模型的连续回复情况。
